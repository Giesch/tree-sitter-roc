## Goal

Build ordered font-lock settings from generated, **face-only** Emacs queries, then append exactly one mode-local `definition-names` override rule for inferred associated annotations. Retain the existing `roc-ts--fontify-inferred-associated-annotation` callback: it colors the captured **identifier span**, not the annotation or its type, as a function only for the six recognized derived names without an immediately following same-name definition (skipping line/doc comments). Otherwise the generated base variable-name face remains. Remove the old handwritten rule list and other highlighting callbacks.

## Depends on

[E01: grammar tag and mode pin](01-grammar-tag-and-pin.md), followed by the new query-contract tag in step 3 below.

## Context

On the supported current runtime, Emacs 30.1 linked to libtree-sitter 0.26.0, `#match?`/`#eq?` compile but `treesit-query-capture` fails with `Invalid predicate`; Emacs's bare `#match`/`#equal` and their sexp expansions fail query compilation under libtree-sitter 0.26. This was reproduced in a private daemon with parser/scanner matching the exact published grammar tag. GNU bug [#79687](https://debbugs.gnu.org/cgi/bugreport.cgi?bug=79687) and upstream [fix b014353](https://github.com/emacs-mirror/emacs/commit/b01435306a36e4e75671fbe7bacea351f89947d5) explain the predicate-name/dispatcher mismatch; the fix is not in the tested Emacs 30.1. The mode-local refinement is intentional, not a grammar-version fallback or a reason to change the system runtime.

The base query in `queries/highlights.scm` already expresses the derive-name predicate and the same-name sibling override for other editors. Keep those semantics and existing cross-editor coverage. Emacs continues to omit **all** predicate-bearing patterns via `$emacs.omitPredicates`; do not enable them globally or replace the callback with an untested predicate rewrite. No grammar, scanner, parser, or system runtime change is needed.
