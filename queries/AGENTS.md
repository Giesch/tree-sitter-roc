# Roc editor queries

Last verified: 2026-10-20

## Purpose and boundaries
Base queries preserve editor captures as the syntax tree evolves. Edit these sources and `query-maps/<editor>.json`, then regenerate `queries-generated/`; generated editor copies are not independent sources.

## Contracts
- `tools/template-queries.js` maps base captures for Helix, Neovim, and Zed across all query families; null, empty-string, or false mappings remove a capture. Their generated non-comment lines have trailing whitespace trimmed.
- `query-maps/emacs.json` covers highlights only. Object mappings provide a face capture and font-lock feature; `$emacs.featureSections` emits feature runs in source order. Removed-only patterns and patterns that predicate-test removed captures are omitted. On Emacs 30.1 with libtree-sitter 0.26.0, `#eq?`/`#match?`/`#not-match?` compile but fail during capture evaluation; their bare spellings fail compilation. `$emacs.omitPredicates` excludes those patterns. The inferred-name capture calls `roc-ts--fontify-inferred-associated-annotation` in the source roc-ts-mode; load that callback before fontification. Built-in-name predicate refinements remain omitted. Keep each retained pattern on one feature. Compile and evaluate sections with the current grammar. The mode does not yet load this file by default; `tools/check-emacs-query-runtime.el` exercises generated sections in a private daemon.
- `node tools/check-emacs-query-generator.js` tests the section generator's lexical boundaries, feature order, removed captures, and mixed-feature failure; `npm run queries:check` runs it before the clean-diff gate.
- String and character captures precede identifiers so interpolation names retain variable faces under sequential override. `number_with_suffix` has an unconditional numeric capture for Emacs; predicates refine it in other editors. Call targets, including pipeline targets, use `function.roc-special.call` without a duplicate definition capture. Doc comments have a comment fallback before the documentation capture. Whole platform references are omitted only for Emacs, while all package URIs retain string coverage.
- The reviewed Helix/Neovim/Zed output is not byte-identical to the prior output: string captures and package URI matching moved, duplicate call and URI captures were removed, doc comments gained a fallback, and the fat-arrow base capture now maps to `operator` in those editors (restoring its prior legacy meaning). The numeric fallback uses existing numeric scopes. Review capture behavior rather than requiring unchanged generated bytes.
- `highlights.scm` captures `"return"` as `@keyword.control.return` and postfix/infix `try_operator` as `@keyword.control.return.roc-special.try`; Neovim maps both to `@keyword.return`. `tools/check-neovim-try-highlight.js` checks both `?` captures with the local CLI.
- Tag-type names use `tag_type name: (tag_name)` with `@type.enum.variant.roc-special.builtin` (mapped to the previous capture in existing editors). Keyword queries match anonymous tokens. Annotation/definition queries use fields and sibling statements rather than the removed annotation nesting.
- Direct expression bodies retain their prior capture ranges even without `expr_body` nodes. Keep retained wrapper captures for contexts that still expose them.
- `locals.scm` captures lambdas, match branches, and blocks as scopes. Declaration-body alternatives enumerate `_expr_inner` subtypes except `anon_fun_expr` and `body_expression`, which already have scope captures. Keep this list synchronized when expression forms change; the regression guard checks it against generated node types.
- Match-branch scopes isolate sibling branches. Current pattern identifiers remain references, not local definitions; these queries do not promise full name resolution.

## Verification
- `npm run queries:check` regenerates output, checks Neovim try captures (including failure-path self-tests), and requires no generated diff.
- `node tools/check-expr-body-captures.js --self-test` checks all six base query families against `tools/expr-body-captures-expanded-baseline.json`: capture names, byte-column ranges, multiplicity, nested scopes, and branch isolation. Intentional contract changes require reviewing captures, not blindly rerecording the baseline.
- These checks establish CLI query behavior, not editor rendering. Verify editor-specific behavior separately when making such claims.
